{{ icon('archive') }} 1. Comment un PST est associé à un compte

Avec les identifiants admin, la plateforme récupère tout l'annuaire Zimbra (SearchDirectoryRequest), puis parcourt le dossier PST et ses sous-dossiers. Pour chaque fichier, elle cherche le propriétaire :

  • Adresse exacte dans le nom du fichier ou d'un dossier parent (ali.bensalah@courdescomptes.nat.tn.pst, ali.bensalah@…/Outlook.pst) : attribution automatique ;
  • Nom correspondant, dans n'importe quel ordre et sans tenir compte des accents ni des mots parasites (archive, backup, années…) : benabdelghaffar.slim, BEN ABDELGHAFFAR Slim (archive 2023), initiale + nom (s.benabdelghaffar), identifiant Windows/AD (Users/sbenabdelghaffar/Outlook.pst), nom de famille seul s'il est unique, petite faute de frappe ;
  • Contenu : java-libpst lit l'expéditeur des Éléments envoyés, le destinataire des mails reçus et le nom interne du PST.
  • Nom et contenu concordants : deux preuves indépendantes, attribution automatique. Deux homonymes possibles ou un contenu qui contredit le nom : la plateforme ne tranche pas et demande validation.
Les attributions par nom ou par contenu sont proposées et doivent être validées (une par une ou en un clic) : la plateforme n'écrit jamais dans une boîte sans attribution exacte ou validée. Si le contenu d'un PST semble appartenir à quelqu'un d'autre, un avertissement est affiché.
{{ icon('key') }} 2. Le jeton délégué : accès sans mot de passe utilisateur

Les comptes sont authentifiés par l'Active Directory : la plateforme ne connaît aucun mot de passe utilisateur. Elle utilise la délégation d'administration de Zimbra :

# 1. Connexion admin (port 7071) — mot de passe gardé en mémoire uniquement AuthRequest(admin, ••••••) → jeton admin # 2. L'admin demande un jeton pour UNE boîte précise DelegateAuthRequest(ali.bensalah@…) → jeton délégué (6 h) # 3. Avec ce jeton, on demande à Zimbra : « qui suis-je ? » (port 443) GetInfoRequest → name = ali.bensalah@…

Le jeton délégué n'ouvre que la boîte demandée. Il est neuf pour chaque compte, renouvelé automatiquement s'il expire, et n'est jamais affiché ni enregistré.

{{ icon('shield') }} 3. La concordance : le verrou de sécurité

Avant toute écriture, la plateforme compare deux informations indépendantes :

nom du fichier PST ali.bensalah@courdescomptes.nat.tn compte renvoyé par Zimbra ali.bensalah@courdescomptes.nat.tn ✓ identiques → import autorisé nom du fichier PST autre.compte@courdescomptes.nat.tn compte renvoyé par Zimbra quelquun@courdescomptes.nat.tn ✗ différents → compte « bloqué », rien n'est extrait ni écrit

Cela garantit qu'un PST ne peut jamais être importé dans la boîte d'une autre personne, même en cas d'erreur de nommage ou de configuration. C'est le seul motif de blocage : le contenu du PST, lui, ne bloque jamais la migration.

{{ icon('file') }} 4. L'extraction du PST (java-libpst)

Le format PST est un format binaire Microsoft. La plateforme utilise java-libpst, une bibliothèque open source qui lit directement les propriétés MAPI du fichier, en lecture seule :

  • Mails : en-têtes d'origine, corps texte et HTML, pièces jointes, messages joints, Message-ID, dates, lu / non lu, indicateur, répondu / transféré, adresse SMTP réelle de l'expéditeur ;
  • Calendrier : rendez-vous, récurrences (quotidienne, hebdomadaire, mensuelle, annuelle), occurrences supprimées ou déplacées, participants, fuseaux horaires, rappels ;
  • Contacts : noms, emails, téléphones, adresses, société, anniversaire, notes ;
  • Tâches : échéance, avancement, priorité, statut.

Les données sont écrites dans work/, puis supprimées dès que le compte est terminé. Les types absents (pas de calendrier, pas de contacts…) sont simplement signalés « absent ».

{{ icon('refresh') }} 6. Fiabilité
  • Simulation : tout le traitement sauf l'écriture, pour valider avant d'importer.
  • Idempotence : chaque élément importé est mémorisé (Message-ID pour les mails). Une relance n'importe que ce qui manque, sans doublon.
  • Reprise : un lot arrêté ou interrompu (coupure, redémarrage) reprend là où il s'était arrêté.
  • Mode delta : n'importer que les mails postérieurs à une date (migration en deux temps).
  • Tolérance : un élément illisible est compté en erreur et journalisé, le compte continue.
  • Parallélisme : jusqu'à 5 comptes traités simultanément.
{{ icon('lock') }} 7. Sécurité
  • Aucun mot de passe utilisateur : délégation d'administration uniquement.
  • Mot de passe admin en mémoire seulement, jamais sur disque ni dans les journaux ; jetons jamais affichés.
  • Écriture limitée aux comptes « prêts » de l'inventaire, après concordance.
  • Import réel derrière une double confirmation explicite.
  • Vérification TLS toujours active (certificat *.courdescomptes.nat.tn).
  • Interface accessible uniquement en local, protégée contre les requêtes d'autres sites.
  • PST en lecture seule, fichiers temporaires supprimés après chaque compte.
